## 4. Current Limitations / Opportunities for Agentification

### 1. Random recommendation

**Limitation:**

v1 randomly selects products rather than making an intelligent recommendation decision.

**Opportunity:**

Replace random selection with a model-driven recommendation decision.

### 2. Limited use of request context

**Limitation:**

Although the API provides user_id and product_ids, the current recommendation logic mainly uses product_ids for filtering and does not meaningfully, use user_id for recommendation decisions.

**Opportunity:**

Agent v2 can use richer context to make context-aware recommendations.

### 3. Limited use of product information

**Limitation:**

v1 retrieves products from Product Catalog, but the recommendation decision is still based on random selection rather than product information.

**Opportunity:**

Agent v2 can use Product Catalog as a backend/tool to obtain richer product information and use it in the recommendation decision.

## 5. Agent v2 workflow design

```
ListRecommendationsRequest
(user_id + product_ids)
        ↓
┌──────────────────────────────────┐
│     Recommendation Agent v2      │
│                                  │
│ Extract Request Context          │
│        ↓                         │
│ Retrieve Product Information     │
│ from Product Catalog Service     │
│        ↓                         │

│        ↓                         │
│ LLM / Model                      │
│        ↓                         │

│ the recommendation request       │
│        ↓                         │

│        ↓                         │
│ Validate Result                  │
└──────────────────────────────────┘
        ↓
ListRecommendationsResponse
(product_ids)
```

## 6. Model / Runtime Selection

### 6.1 Model Selection

**Selected Model: Gemini**

Gemini is selected as the model for Agent v2.

### 6.2 Model Access / Runtime

The Agent will access Gemini through Google Cloud services rather than using a self-hosted model runtime.

### 6.3 Selection Rationale

Because the project already been decided to be deployed on Google Cloud Platform (GCP), using Gemini provides better integration with the existing GCP-based architecture. Additionally, it avoids introducing an additional self-hosted model runtime.

## 7. Limitations of the Recommendation Service for Agentification

- **Limited Output Space**
  - The Recommendation Service was initially selected because recommendation tasks seem well suited to LLM-based decision making. However, the existing gRPC API only returns `product_ids`, and there is no space to output the recommendations or reasoning generated by the model.

- **Limited Decision Space**
  - Only a small part of the existing Recommendation Service logic can be meaningfully replaced by an LLM. The main change would be replacing the current random product selection with model-driven recommendation, so the agentification level is relatively limited.
